# Résumé

Source content and build scripts for Kieran's curriculum vitae (CV), compiled
from LaTeX to PDF, and converted to Word (.docx). Releases are tagged in Git and
built automatically by CI.

The capitalized words REQUIRED, MUST, MUST NOT, RECOMMENDED, SHOULD,
SHOULD NOT, OPTIONAL, and MAY are to be interpreted as described in
[IETF RFC 2119](https://www.ietf.org/rfc/rfc2119.txt).

## Tech stack

- LaTeX (`pdflatex`), from [TinyTeX](https://yihui.org/tinytex/) 2023.02
  (TeX Live 2022), installed by [mise](https://mise.jdx.dev) and pinned in
  `mise.toml`. LaTeX packages come from the frozen TeX Live 2022 archive, so
  the build is reproducible, and identical on the host, in the devcontainer,
  and in CI.

- [Pandoc](https://pandoc.org), also pinned in `mise.toml`, to convert the same
  LaTeX source to Word, with a Lua filter and a reference .docx for the styles.

- GitHub Actions, to build the PDF and attach it to GitHub releases on tag push.
  The Word version is built locally only, not in CI.

## Project structure

- **[src/kieran-potts-cv.tex](./src/kieran-potts-cv.tex)** \
  The CV source, compiled by `pdflatex`.

- **[src/docx/](./src/docx)** \
  The Word build's inputs: `macros.tex` (Pandoc-friendly replacements for the
  CV's macros), `filter.lua` (maps the document onto Word styles), and
  `reference.docx` (the styles and page setup). See
  [docs/development.md](./docs/development.md).

- **[mise.toml](./mise.toml)** \
  Pins TinyTeX and Pandoc. Do not bump TinyTeX without comparing the PDF:
  later TeX Live releases change the CV's layout. Likewise, compare the .docx
  before and after bumping Pandoc.

- **[run/install](./run/install)**, **[run/build](./run/build)**,
  **[run/build-docx](./run/build-docx)** \
  Dev scripts. `install` installs TinyTeX, Pandoc, and the LaTeX packages the
  CV uses; `build` runs `pdflatex` (via `mise exec`), and `build-docx` runs
  Pandoc, both outputting to `dist/`. CI runs `install` and `build`, but not
  `build-docx`.

- **[dist/](./dist)** \
  Build output, including `kieran-potts-cv.pdf`, `kieran-potts-cv.docx`, and
  other compiler artifacts. Not committed as source of truth — regenerated by
  `run/build` and `run/build-docx`.

- **[CHANGELOG.md](./CHANGELOG.md)** \
  Per-release notes, aligned with Git tags.

## Tools

- `make install` (or `sh run/install`) to install the LaTeX toolchain. Run it
  once on a new machine or devcontainer, and again after `mise.toml` or the
  package list in `run/install` changes.

- `./run/build` to compile `src/kieran-potts-cv.tex` to
  `dist/kieran-potts-cv.pdf`. It stops at the first LaTeX error, rather than
  prompting, so it runs unattended.

- `sh run/build-docx` (or `make build-docx`) to convert the same source to
  `dist/kieran-potts-cv.docx`.

## Rules

- MUST run `chmod +x run/*` after cloning, since the scripts are not
  executable by default on all systems.

- RECOMMENDED to tag releases as `v[major].[minor].[patch]` with an annotated
  tag (`git tag -a`), including a summary of changes in the tag message, and
  push with `git push --follow-tags`. CI creates the GitHub release and
  attaches the compiled PDF automatically. The Word version is not released.

- SHOULD run `run/build-docx` and check the Word version after changing the
  structure or macros of `src/kieran-potts-cv.tex`, since Pandoc parses only a
  subset of LaTeX. New custom commands MAY need a counterpart in
  `src/docx/macros.tex`. Optional arguments MUST stay on the same line as their
  command, eg. `\resumeSubheading[0pt]`, or Pandoc misreads them.

- Release notes SHOULD be formatted using Markdown, consistent with
  `CHANGELOG.md`.
